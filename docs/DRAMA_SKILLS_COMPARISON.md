# 火宝内置与 Drama Skills：本次接入对比

比较对象：火宝 v4.0.11 基线 `b48e6b2` 的实际提示词、技能与工具链；Drama Skills 0.11.2，固定提交 `3d813c30871b4db5f2387d83bdc3a49db8ce7b2b`。检查日期：2026-11-08。

结论：**针对短剧的剧作、分镜和连续性规则，Drama Skills 更适合当前的质量改进；现有火宝应用更适合承担资产管理、保存、生成任务和工作台交互。默认使用二者适配后的增强方案。** 这是对规则与实现的比较，还不是同模型成片盲测结论。

## 逐项比较

| 维度 | 火宝当前内置 | Drama Skills | 本项目采用 |
|---|---|---|---|
| 剧本 | 保留原情节、格式化、对白驱动，每场 30–60 秒 | 目标、阻力、因果、可见状态变化、潜台词，清理重复解释 | 增强剧作规则，继续保存到当前集 scriptContent |
| 镜头时长 | 8–15 秒生成段，2–4 子镜头；全剧字数/500 推总量；视频正文按 3 秒切段 | 镜头职责、完整发声、动作和反应决定时长，结合已确认的模型能力 | 默认一个连续镜头一条记录，不强制等长；生成素材长度与剪辑保留区间区分 |
| 分镜导演 | 已有节拍、景别、机位、动作和结果字段 | 进一步细化场景站位、轴线、视线、交接接触与物件落点 | description 写职责/来源/起点/声音，result 写终点，复用已有字段 |
| 连续性 | 绑定人物、场景和道具，复用参考图 | 身份与变体区分、状态生效范围、跨镜连续性锁 | 写进现有资产字段；没有新增独立 Look/状态数据表 |
| 首帧 | 为生成段提供单帧构图 | 只冻结起点，避免首帧提前出现终点状态；参考图职责明确 | image_prompt 保存冻结起点；读取上下文补齐首尾帧和参考图字段 |
| 视频提示词 | 已接工具保存与 @资产、#音色引用，偏固定时间段模板 | 起点—主变化—次级反应—声音—终点，含按模型区分的知识 | 保留应用引用语法，采用动作与声音规则；未知模型能力不猜 |
| 图片提示词 | 角色三视图、空场景、白底道具，可直接进入现有生成接口 | 识别锚点、单一状态、参考用途与文字政策更细 | 保留入口交付形态，补充识别与连续性规则 |
| 审片与剪辑 | 本 fork 已实现人工审片、入出点、合格镜头导出 | 有带证据审查、可用片段、对白尾音和接镜方法 | 审片页增加人工检查提示，沿用已有 FFmpeg 导出 |
| 开箱执行 | 本应用原生 Mastra 工具、数据库、任务与界面 | 原生面向文件、CLI 与自己的生产适配器 | 使用火宝执行链，不能直接把上游文档指令原样叠加 |

## 已接入范围

在「设置 → Agent 配置 → 创作方案」选择：

- **Drama Skills 增强**：默认。4 个 Agent 加载适配技能，覆盖剧本、视觉资产、分镜、图片提示词、视频提示词五个创作阶段。原 System Prompt 和原技能不与增强规则混载；原生 Mastra 技能目录也随方案切换。
- **火宝内置**：保留原有创作提示词与可编辑技能作为对照。两种方案共用数据、工具和生成接口。

方案在请求开始时固定，覆盖聊天、自动资产提取、图片提示词与批量视频提示词入口；切换后不会重写已有素材。设置页显示当前实际生效指令；增强规则可在 Skills 标签内编辑，来源快照独立保存。

工程上另外修正了三处影响接入的问题：

1. 单镜按钮和批量视频任务的追加消息不再强制三秒切段；增强提取不再沿用“最多三个道具”的硬编码要求。
2. 增强剧本读取优先使用当前已编辑剧本，保留原文供查证；改写工具不再额外注入固定场景长度。
3. 分镜上下文补齐 result、image_prompt、机位、运镜、真实首尾帧/参考图记录及项目画风，避免下游提示词丢掉起终状态。

本地保存了 7 个上游技能的完整目录（上述 5 个加 review/edit），共 112 个来源文件，附 MIT LICENSE 和 SHA-256 清单。运行时只默认注入当前 Agent 的简明适配技能，知识参考按需读取，不把整套资料一次塞给模型。review/edit 本次接入的是人工审片提示与方法，没有接入它们的独立 CLI 渲染器或自动视觉审查。

没有接入上游的独立 Dashboard、produce 供应商链路、小说分析、长篇分集开发和拉片入口。本次也没有新增 ComfyUI/Qwen3-TTS 网页生成适配器。

## 对《豪门赘婿》的意义

此前的本地版本是固定镜长、动作受限和简单拼接。增强方案会让下一轮创作先明确“这镜为什么拍”“谁因什么动作发生变化”“对白能否说完”“物件与视线如何接到下一镜”，再生成提示词。它有望减少无效镜头和连续性错误，让审片有具体依据。

提示词规则不会自动提高基础视频模型的脸部稳定性、肢体运动、口型或音质，也不会自动修复已导入的 12 段素材。仍需真实参考图、可用模型与多轮审片证明改进。

## 验证与边界

- 后端 TypeScript 检查通过。
- 4 项集成测试通过：方案 API/持久化/请求快照，4 个注册 Agent 的实际指令与原生 Workspace 切换，当前剧本及 2.5 秒镜头起终状态的保存回读，来源快照哈希。
- 5 项原有审片与 FFmpeg 导出测试通过。
- 前端生产构建通过；真实 Edge 浏览器验证双向切换、生效指令、技能归属、12 镜素材保留及人工审片提示，无页面运行错误。
- 4 个新适配技能通过 skill-creator 格式校验。
- 验证时工作台 AI 服务配置为空，未调用文本/图片/视频模型，未做成片 A/B，未将规则对比伪装成质量评分。

后续比较应复制同一剧本到两个测试集，保持模型、参数、参考图、候选数量和预算一致，分别用两种方案生成。比较可用镜头比例、连续性缺陷、对白完整率、返工次数及人工观看判断；记录具体镜号和证据。现有测试只证明接入有效，不证明模型创作质量。
